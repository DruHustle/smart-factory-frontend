# Smart Factory telemetry provenance policy 1

This repository owns its validator and fixture copy. No peer application or shared custom schema package is required. `fixtures/telemetry/provenance-v1.json` contains 99 equivalent acceptance and normalization examples, independently exercised in Node, .NET and Python.

Absent or root `null` integration retains legacy unknown provenance. An object requires `mode` (`live`, `simulated`, `replay`) and `gatewayReceivedAt`. Child nulls and unknown keys are rejected. IDs (`scenarioRunId`, `replayRunId`, `sessionId`, event `id`/`code`) are ASCII `[A-Za-z0-9:_.-]{1,128}`: preserve case, reject blank/numeric/null/oversized values. Simulated requires scenarioRunId, replay requires replayRunId; replayRunId is rejected outside replay. A scenario ID may accompany replay to identify its source.

Receipt timestamps use Gregorian years 0001–9999 and exact `YYYY-MM-DDTHH:MM:SS[.fraction](Z|+00:00)`, with 1–9 optional fractional digits. Validate actual calendar dates, hours 00–23, minutes/seconds 00–59. Local time, nonzero offset, -00:00, leap seconds, invalid days and permissive date rollover are rejected. Normalize to uppercase Z and exactly three millisecond digits, truncating further precision. Never substitute current time for malformed receipt time. Measurement timestamp, gateway receipt and server ingestion time remain separate.

Optional sequence is an integer 0–9007199254740991 (including JSON 1.0), never boolean/string/null. sourceQuality defaults unknown, accepts good/bad/uncertain/unknown. sourceConnection defaults unknown, accepts online/offline/unknown. timestampOrigin defaults device, accepts device/gateway. retained defaults false and must be boolean. sourceEvents defaults [], maximum 20; each strict object requires id, origin=source, code, state=active/cleared, componentId. Component UUID accepts RFC variant versions 1–8 plus nil/max, normalized lowercase. Canonical compact UTF-8 provenance is at most 8192 bytes; MQTT message maximum is 16384 bytes. Existing authenticated HTTP request limits remain in effect; formatting whitespace does not count against canonical provenance size.

Validation occurs before ordinary persistence/forwarding. Errors are bounded codes/field errors without echoing industrial values or credentials. Edge serial input can stamp receipt when the field is absent; a present malformed receipt is never repaired. Broker-retained status is ORed with a declared retained flag, never erased.

## Delivery and recovery

Backend delivery revalidates historical queued metadata. Invalid historical provenance and receiver 400/413/415/422 enter durable quarantine, without setting DashboardForwardedAt. 401/403 are credential quarantine; other unexpected 3xx/4xx are configuration quarantine. 404/408/409/423/425/428/429 and 5xx retry the same ingestion identity. Transport timeouts are unconfirmed outcomes, not proof of rejection. Bounded exponential backoff and bounded Retry-After (1–300 s) apply; after 12 unsuccessful transient attempts the backend preserves a retry-exhausted quarantine record. Redirect following is disabled. The optional export worker independently preserves its existing bounded quarantine/outbox policy.

Migration `20261026_telemetry_quarantine.sql` adds DeliveryQuarantinedAt and DeliveryErrorCode (max 128 characters), and indexes deliverable records. Operators can inspect ID, IngestionId, attempts, acknowledgement, quarantine time and code in the application's own telemetry database. Receiver bodies and tokens are not stored as diagnostics. To deliberately retry after fixing a configuration/validation problem, review the retained row and correct its provenance if necessary, retain IngestionId, clear DeliveryQuarantinedAt/DeliveryErrorCode, reset DeliveryAttempts and set NextDeliveryAttemptAt to now. Do not set DashboardForwardedAt: only a receiver 2xx establishes acknowledgement. Invalid ingress is rejected before queue insertion. A mock receiver demonstrates policy, not external-consumer compatibility.

## Verification

Before the fix, the locally owned fixture suite reproduced 16 Node and 72 .NET disagreements; edge forwarded invalid metadata. Focused backend queue tests also failed for historical invalid metadata, repeated 422 and timeout recovery. After alignment all 99 policy cases pass in each implementation; delivery regressions cover permanent quarantine and transient recovery without source identity changes. The repository evidence records exact final tests, source commits and actual Smart Factory MQTT simulated/replay traversal separately.
