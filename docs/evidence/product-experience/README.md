# Before/after rendered application evidence

All records in these captures are isolated synthetic fixtures. The images show implemented application routes, not production data. Per-image JSON records width/theme/source and fixture scope. Historical acquisition remains historical; no physical machinery or external provider was used. The oversized before mobile Analytics images show the first viewport; their JSON/manifest records the full 9,217-pixel document height. After captures show the complete compact page.

The full after matrix covers 360, 390, 768, 1024 and 1440 pixels, both themes. Representative desktop/mobile captures were refreshed after the final Assistant attribution fix. The before captures use historical UI source `81bdd2f`; each after capture records its actual reviewed source.

## Accessibility and measurement notes

The checked 200% layout is an emulation using a 720 CSS pixel viewport and device scale factor 2. [Light](after/zoom-light-1440.png) · [Dark](after/zoom-dark-1440.png). Actual browser-chrome zoom and physical mobile GPU behavior are separate acceptance tasks.

[Resolved light-theme contrast](after/contrast-light-390.json) · [Resolved dark-theme contrast](after/contrast-dark-390.json). Text pairs pass 4.5:1 and controls/charts/focus pairs pass 3:1. Semantic colours retain labels. Keyboard navigation, mobile drawer Escape/dismiss/return focus and 3D component sheet behavior are exercised in the browser suites.

See the [finding disposition and acceptance report](../../product-experience-qualification.md) and [machine-readable qualification](qualification/README.md).
