# Incremental OT workflow baseline and evidence limitations

This map records the incremental candidate `ff299a33d0e3c5f335ca47eb0615a29c84870657` and its known gaps at handoff. The [expanded OT operations guide](ot-operations.md) describes the subsequent implementation. Neither document is a commissioning record. Demo data is simulated; operational conclusions require commissioned sources and suitable quality and freshness rules.

The API advertises `ot-incident-review-v1` when it supports priority ordering and categorized notes. Against a compatible older API, Overview links to the alert queue without claiming priority, and investigation notes remain uncategorized. The separate `ot-follow-up-actions-v1` capability enables action records and the Overview follow-up list. On an older API, action controls are hidden and their stored data is preserved. Deploy the API before the UI; a compatible fallback keeps ordinary notes available without silently dropping categories.

## Reference workflows and Smart Factory decisions

- [Ignition alarming](https://docs.inductiveautomation.com/docs/8.3/platform/alarming) documents separate active/cleared and acknowledged conditions. Smart Factory's existing review status does not supply a verified physical-clearance signal, so this implementation states that limitation instead of treating acknowledgement as clearance.
- [PTC Action Tracker](https://support.ptc.com/help/digital_performance_management/r10.0/en/dpm/digital_performance_management/action_tracker/action_tracker.html) describes equipment-linked actions with owners and status. Smart Factory uses incident-linked action records with independent owners and status plus append-only review history. Shift scheduling and comparable before/after analysis remain gaps.
- [PTC Performance Analysis](https://support.ptc.com/help/digital_performance_management/r10.0/en/dpm/digital_performance_management/performance_analysis/performance_analysis.html) and [Siemens downtime analysis](https://docs.industrial-operations-x.siemens.cloud/r/en-us/insights-hub-oee/data-visualization/downtime-analysis/downtime-analysis?contentId=EzfSf8TPfzz6Df3AOmyPNA) describe drilling into losses and downtime. Smart Factory should only show comparable production metrics when its own inputs and time model support them.
- [AVEVA PI Vision](https://www.aveva.com/en/products/aveva-pi-vision/) describes asset-context displays and interactive trends. Smart Factory keeps its own asset workspace and trend navigation rather than copying a vendor layout.
- [IBM Maximo Monitor 9.2](https://www.ibm.com/support/pages/ibm-maximo-application-suite-monitor-component-920) describes missing-data alerts and parent/child aggregation. Smart Factory keeps missing or unverified evidence visible and does not equate a gateway connection with a fresh process sample.
