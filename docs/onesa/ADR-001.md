# ADR-001: optional persistent producer fan-out; proposed consumer contract

Status: accepted for producer implementation; consumer acceptance pending.

The dashboard is a React/Vite client plus Node/Express/tRPC API using PostgreSQL/Drizzle and Redis. The .NET TelemetryService already subscribes to MQTT and durably forwards to the dashboard. The Pi gateway owns device acquisition. No additional subscriptions or equipment pollers are needed.

The adapter belongs in the existing server API, after attribution and persistence. It uses the same PostgreSQL transaction to capture telemetry, and an independent worker to normalize/deliver. No network call is made on acquisition. Optional integration failure must not disable local monitoring. Bounded storage uses explicit discarded counters, never silent deletion. Delivery is at least once, with immutable event IDs and receiver acknowledgments. Destination, workspace and credentials are deployment-owned configuration. Browser operators may edit mappings, not destinations or credentials. Shared demo identities cannot access private configuration.

Inspection: Onesa main `65d9346f297ee8869595b38634fda020bf9607f9`. Its `app/industrial_evidence.py` defines `onesa-industrial-evidence-v1`, synthetic-only file input. `app/industrial.py` provides `/api/v1/industrial/imports/preview` and user-owned investigations, using session authentication. These are not equipment ingestion or workspace registration APIs. No pump/motor GLB, twin component IDs, AAS importer, service credential scope, high-frequency ingestion, partial receipt or deep-link route was found. A proposed service adapter cannot claim compatibility with those absent features. No sibling code is modified.

Decision: `urn:smart-factory:onesa-proposed:1.0.0` is a proposed contract owned here until Onesa adopts or replaces it. Zod is the single source; generated JSON Schema/OpenAPI and a hash lock detect drift. A local contract receiver enforces credential-bound workspace scope, immutable deduplication, partial receipts and separate live/simulated/replay history. Receiver behavior is evidence only for the proposed contract. Advanced twins, assistant tools and agent execution remain consumer responsibilities.

Source UUIDs and external asset identifiers survive rename, tag changes and geometry changes. Installed instances refer to reusable type IDs. Mapping updates use optimistic versions and cannot reroute queued events. The adapter does not delete consumer assets/history or overwrite consumer-owned annotations, rules or geometry. No actual registration call or twin navigation is possible until the consumer supplies those contracts.
