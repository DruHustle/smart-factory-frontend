# Editable, resettable demo

Open **Editable demo** from Tools & settings or the Overview banner. Each visitor gets an independent browser workspace seeded from the approved demonstration inventory. Create equipment, edit its identity, configure simulated connections, design [factory layouts](factory-layouts.md), generate readings, cross threshold rules, acknowledge and resolve incidents, explore network scenarios, record security investigation decisions, and try firmware queue/completion steps. All records remain explicitly simulated. A sample AASX action creates equipment from reviewed example identity fields; it does not parse or publish an uploaded package.

Use **Demo role** to sign in with an existing public demo account while retaining this browser's edits. Viewers explore and design personal layouts. Operators generate telemetry and act on incidents. Engineers also manage equipment, threshold rules, sample firmware and security decisions. Administrators additionally manage sample users, acquisition settings, notifications and backup restore. Creating a sample user does not create a login or grant actual permissions; only the authenticated role controls the demo UI.

Changes persist across refresh in this browser. Another browser has its own workspace. **Reset demo** asks before restoring the reference inventory and clearing sandbox edits, workflow history and samples. Export a backup first to keep your work; an administrator can restore a validated backup. Factory layout drafts are retained separately. Storage failure is visible and exports remain available. Reports download local simulated inventory as CSV.

The Assistant can answer operational questions about a bounded snapshot of this browser workspace, captured with each submitted question. Generic explanations do not send this state. Answers label browser simulation and never infer physical connectivity, timing, fault cause or actual firmware installation.

The Digital passport section prints the selected simulated equipment's product fields. Existing reference assets also support signed-in printable passport previews. Neither action publishes an asset. Operational writes, private administration, real notifications, credentials, external configuration and hardware commands retain their existing server authorization boundaries. Firmware completion is an explicit simulation; no delivery agent is claimed.
