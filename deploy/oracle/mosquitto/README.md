# Smart Factory MQTT broker

This stack stages Mosquitto on the existing Oracle host. It does not move clients or replace CloudAMQP by itself. Use the exact immutable image in `compose.yaml`; the listener requires TLS, individual credentials and topic ACLs. The broker persists sessions and queued QoS 1/2 messages in a named volume and uses `restart: unless-stopped`. The health probe authenticates over TLS using a dedicated identity. Caddy remains the certificate issuer; a bounded systemd timer copies only the current Smart Factory API certificate and key into the broker's private directory and reloads Mosquitto after renewal.

`bootstrap-staging.sh` creates a new `/opt/smart-factory-mqtt` only if absent, generates unique random credentials in root-only files, and starts the broker bound to loopback. The client passwords are never embedded in this repository or command-line arguments. Review the fixed site, line and gateway ACL before using another deployment. `probe-staging.sh` sends synthetic QoS 0/1/2 traffic only to an isolated synthetic topic on that broker. The developer smoke test `python3 scripts/mqtt/broker-smoke.py` uses its own disposable TLS certificate and Compose project to check ACLs and persistence.

A production cutover additionally requires a reviewed network rule, tested reachability and hostname-verified TLS from the gateway, private distribution of each dedicated credential, one worker at a time, a confirmed gateway restart and end-to-end telemetry/command verification. Keep CloudAMQP and its configuration backup until those checks pass. QoS is negotiated per MQTT hop; broker capability alone does not prove that publishers and subscribers are using the requested level. Do not report a requested value as applied until each participant confirms it.

Docker restarts the broker after its process exits. For a running but unhealthy broker, `../broker-controller.py` uses the existing bounded recovery logic with a separate state directory, a strict broker identity and the shared release lock. Install the reviewed `broker-controller.py` and matching `container-controller.py` together under `/usr/local/lib/smart-factory/`, and install the matching `smart-factory-mqtt-controller.service` and `.timer` under `/etc/systemd/system/`. Run the broker controller without `--apply` first, verify its decision, then enable the timer. It waits three minutes, rate-limits recovery, never starts an intentionally stopped container and fails closed if its identity or release lock is wrong. Check `systemctl status smart-factory-mqtt-controller.timer` and `journalctl -u smart-factory-mqtt-controller.service`; stop the timer for planned broker maintenance. Its Docker access is privileged, and a persistent unhealthy condition still needs investigation.

If startup or cutover fails, leave or return clients to their previous broker using their retained configuration backups. Do not delete the old broker, its queues, the new broker's persistent volume or existing recovery evidence as part of this staging process. A copied certificate is privileged material; never place it or generated credentials in source control or diagnostic output.
